Trade card data: what's already in the repo

This review went through everything the trade card fetches or calculates and checked it against existing code. It used /simplify, reuse only, with two read-only agents. Each function named below was confirmed to exist. Nothing has been changed yet. In total, roughly 150–180 lines could be replaced by calls to existing code, and one of the swaps also fixes a real bug.

Two places that repeat a rule instead of a function

  • Years of control. contractYears / controlYears in deal.js repeat the arbitration-at-3-years, free-agency-at-6-years rule that already lives in api/person/contract/view.js (FREE_AGENCY_SERVICE). The trade card's "~" estimate, which projects past the contract records from service time, is new and worth keeping. The constants should come from one place.
  • Pitcher role. This already uses the team page's roleFromCounts.

Already reusing existing code

The 40-man roster (fetchTeamRoster), contracts (fetchTeamContracts), WAR (fetchWarData), prospect ranks (fetchTopProspects / prospectRankById), pitcher role (roleFromCounts), and the level-lines script, which uses qualifiedMetrics.

Genuinely new (nothing to reuse)

  • The whole-organization roster read that includes each player's current affiliate. fetchTeamRoster can't request that detail, though an option on it would make this reuse instead.
  • The how-acquired script (gen-trade-pedigree.mjs), the level-percentile file, and the draft-pick list (gen-cb-picks.mjs).
  • Next season's pay, the minor-league option text, salary retention, the deal summary, the wire sentence, the before-and-after depth chart, and the row display helpers.

Suggested order

  1. #5 draftInfo: it fixes a bug and is a one-line swap.
  2. #10, #11, #8: exact matches, safe.
  3. #1 and #3: the biggest cut. Each touches the trade card's data loader, so check the result in the browser.
  4. #9: decide whether the trade card should follow the app's "$780K" money format.
  5. #2, #4, #6, #7, #12: shared functions that need a small extension first.
