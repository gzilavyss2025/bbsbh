Ask the Play Log: filter layout spec

Agreed with Gary on 2026-11-18. Route /research, code in src/screens/research/. Mockup: layout-directions.html beside this file. Critique: critique-layouts.html. Design only; the data work (new filters, baseline, lead facts, row links) is the data stream, PR #3194.

Decisions

  • Users: mid-game fans and researchers equally.
  • Way in: filters only. The typed question box (AskBar.jsx) is removed from the page.
  • Old ?q= links: dropped. A typed question in the URL is ignored; the other filter keys still load.
  • Quick-adds: Plays mode only.
  • Visible filters: only the ones you've set, plus four quick-adds; everything else in one grouped drawer.

Page order (phone and desktop)

  1. Mode tabs: Plays · Games · Streaks, first thing under the page title. They move up from under the box.
  2. Filter row (Plays mode), wrapping:
    • Each set filter is a solid marker-fill chip: value text + ×. Tap the chip to change the value; × clears it.
    • Then a dashed chip for each unset quick-add: + Batter · + Pitcher · + Result · + Seasons. Setting one turns it into a solid chip.
    • Last, a dark + More filters button. When drawer filters are set it reads "+ More (N set)".
  3. Empty state (nothing set): the "Try one" questions as whole-row doors (Last time · How often · Leaders · What happened next). No helper lines.
  4. Question switch (ASKS, ?ask=): stays, directly under the filter row once any filter is set; hidden on the empty page. Labels renamed in code: Who most → Leaders, What happens → What happened next. Games drops What happened next, as today. The Leaders rank control (Count | Rate, min PAs) sits with the Leaders answer, not in the drawer.
  5. Answer once a filter is set: the lead facts card (data stream), then rows.
  6. Coverage note (seasons searched, filters that skip older years): one line at the foot of results, not between tabs and card.

More filters drawer

  • Phone: bottom sheet. Desktop (≥ 768 px): a panel that opens in place under the filter row; the button reads "− Fewer filters" while open.
  • Top: a find box that matches filter names and values ("100", "walk-off", "sinker").
  • Five groups, in this order. ● = added by the data stream.
    GroupFilters
    WhoBatter hand, Pitcher hand, Batting slot, Pitcher role ● (role, single), Times facing pitcher ● (tto). Later, not in PR #3194: Position / pinch hitter, Rookie / debut
    PitchFinal pitch type, Final pitch location (Inside / Middle / Away), Pitch speed ● (range), Count reached ● (cnt, exact counts), Final count ● (fc, ahead / even / behind / exact)
    ResultBatted ball type, Batted ball location, Exit velocity ● (range), Launch angle ● (range)
    SituationOuts, Runners, Score, Moment, Leverage, Inning, Win prob (today's wp=1 switch, as a row beside Leverage)
    GameClubs (three pickers: Batting club team, Pitching club pteam, Ballpark park), Game type, Series game, Month, Home or road
    Batter, Pitcher, PA result and Seasons are the quick-adds; they also appear in the drawer (Who / Result / Game) so find works on them.
  • Range filters (exit velocity, pitch speed, launch angle) open a min / max number pair, blank = open, not a value list. Chip reads "≥ 95 mph", "10°–30°", "≤ 80 mph". No Invert.
  • Several values: a second pick on a set filter joins the same chip ("Single, Double"); past two it reads "PA result: 3". Invert lives in the value editor; the chip reads "Not Home run". single filters (bh, ph, ha, role) swap value and never invert.
  • Editing a chip: tapping a set chip opens the drawer at that filter's row, expanded (bottom sheet on phone). Batter / Pitcher open the existing player search; Seasons opens the From / To selects (SeasonsCard).
  • Groups start collapsed except any group holding a set filter. The find box matches filter names only in v1.
  • A set filter shows a tick in the drawer. Picking a value adds its chip at once. The sheet's close button shows the live count ("Show 9 plays").
  • A filter the season range can't answer (unsupported() in filters.js) shows muted in the drawer with "from 2015" or "not built yet". If it is already set, its chip stays, struck through, with the same words.
  • Searching: each pick searches at once, as today (Stop stays). The sheet button reads "Searching…" until the count is known, then "Show N plays". With 0 matches the answer area reads "No plays match" and the set chips stay above it to clear.

Games and Streaks

Same chip row and + More filters, no quick-adds. The drawer lists only that mode's filters (GAME_CHIPS / STREAK_CHIPS) plus the game-total or streak cards (g: / s:) as their own group. The Streaks Players switch (Batters / Pitchers) stays under the tabs. Streak presets stay as the empty-page doors.

Removed

  • AskBar.jsx, its "For example" line, and the typed-question parser (ask.js, parseAsk). Do this after PR #3194 merges, since it edits the same files.
  • "Build your own: start with a filter on the left".
  • The left filter column and "Add a filter: Choose…" select.
  • The data line between tabs and card (moves to the foot).

House rules that bite

  • Chips, drawer rows, doors: 44 px min height.
  • Marker yellow is a fill only (set chips), never text. Tokens, not hex; type roles from tokens/typography.css.
  • Info text (the info strings in filters.js) opens by tap in InfoPopover from the drawer row, never shown by default.
  • Words: "Any" everywhere (not "Anyone"); "Leaders"; "What happened next".
  • Filter state stays in the URL with today's keys. Exception from PR #3194: old cnt=ahead|even|behind links should load as fc (data stream to confirm).

Note for the build

"Try one" doors set filters directly (no typed text behind them). Their wording may change with the new filters; the data stream owns which questions appear.
